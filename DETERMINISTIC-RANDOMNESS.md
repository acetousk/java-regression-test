# Deterministic randomness: audit and implementation

## Where the failed UUID came from

`moqui.server.Visitor` declares `sequence-primary-use-uuid="true"` in
`framework/entity/ServerEntities.xml` (Rust: `runtime/base-component/framework/entity/ServerEntities.xml`).
Java's `EntityFacadeImpl.sequencedIdPrimary[Ed]` used `UUID.randomUUID()`.
Rust's `entity/sequence.rs::uuid_v4` used `getrandom::fill`, then set UUID v4 and
RFC variant bits. Both were correct random UUID generators, but neither was
controlled by the logical clock. The first Step 5 write therefore differed.

No UUID equivalence/normalization or database-comparison exemption was added.

## Seeded source

The transaction coordinator now owns application entropy as well as time.
Both engines POST this request to the existing hook, without opening a database
transaction or waiting for a peer:

```json
{"version":1,"run_id":"<run>","engine":"java","event":"random","domain":"entity:moqui.server.Visitor","length":16}
```

Response: `{"bytes":"<lowercase hex>"}`. Invalid requests, transport/JSON errors,
malformed responses and journal failures fail closed; there is no OS fallback in
deterministic mode. Requests are bounded to 4096 bytes and printable ASCII domains.

* One 256-bit seed per run; `--random-seed` accepts exactly 64 lowercase hex characters.
  Omit it to obtain a fresh seed from infrastructure OS entropy.
* Per-engine, per-domain, per-phase draw counters start at zero. The engine name,
  transaction sequence, transaction nesting and requested byte length are **not**
  inputs to the byte generator. One engine cannot consume the other's draws.
* Block `b` of draw `n` is HMAC-SHA256 keyed by the seed, over the ASCII encoding of
  compact JSON `["moqui-random-v1", phase, domain, n, b]`. Concatenate blocks and
  truncate to the requested length. Longer requests preserve the same prefix.
* UUIDs use 16 bytes, set byte 6's high nibble to 4 and byte 8's high bits to `10`,
  then use standard UUID hex formatting in both languages.
* Unit doubles use the top 53 bits of a big-endian 64-bit draw divided by `2^53`.
  Bounded integers use a big-endian unsigned 32-bit draw with rejection sampling.
  Random strings retain URL-safe base64 and truncation to the requested length.
* For `--deterministic --skip-step-4`, loading draws have phase `loading`; activation
  after loading starts separate `activity` streams. Different loading draw counts
  cannot shift Step 5's ids. In full comparison mode the stream is `activity` from
  startup. Rollback does not rewind entropy; factory restart does not reset it.
* Different internal read/metadata/trace counts do not shift entity streams. The
  same semantic domain must still perform corresponding draws in corresponding
  order. This does not reorder arbitrary concurrent work or fix different business logic.

The seed is retained in private `random-seed.json` (0600); `random-draws.jsonl`
records engine, phase, domain, draw index and length, **not generated bytes**.
The engine logs record random request metadata, not generated tokens. The final
coordinator report includes per-domain draw counts as diagnostics. Unmatched
internal domains are not database equality exemptions. Database writes remain strict.

**Test mode makes tokens, codes, salts, session ids and generated secrets predictable.
Never enable it on a production or shared deployment. Treat seed/run evidence as
sensitive and use fresh isolated databases and private runtimes.** Disabling
`MOQUI_DETERMINISTIC` retains normal randomness. A repeated seed reproduces entropy,
not all inputs: time, externally supplied values and shared per-run encryption
keys have their own lifetimes.

## Explicit boundaries found by the audit

These are not new comparison approvals and must not be described as globally
reproducible application behavior:

* **Infrastructure isolation:** controller database passwords, seed creation and
  the shared per-run field-encryption key use real entropy. Rust report temporary
  directories (`screen/statics/report.rs`) keep real entropy to avoid predictable
  shared `/tmp` paths. They are not persisted business values.
* **Cryptographic transport/internal defenses:** Rust RSA signing blinding
  (`moqui-lib/src/signer.rs`), TLS/cluster certificate key generation, TLS/SSH
  handshakes and HTTP clients' internal randomness stay cryptographically random.
  RSA PKCS#1 v1.5 blinding does not change the resulting signature. Persisting or
  comparing transport keys/certificates needs an explicit fixture, not a seeded
  production-strength key generator.
* **Third-party wire serialization:** JavaMail/lettre multipart MIME boundaries,
  transport retry internals and remote-system-generated ids are not controlled by
  the application-entropy adapter. Persisted framework Message-ID is controlled;
  full email wire bytes are not claimed equal. External integrations require
  fixtures/isolated endpoints and their own regression specs.
* **Browser-owned code:** framework Assist UI nonce generation and vendor
  Select2/Quasar/QZ-tray code use browser `Math.random`; WebCrypto/TLS and browser
  cookie internals are not patched here. The new QuickJS hook is server-side,
  not a claim that browser randomness is controlled. A test exercising those UI
  features needs a browser-side deterministic-input adapter.
* **Arbitrary application/plugins:** direct `Math.random`, `SecureRandom`,
  custom PRNGs, SQL `random()`/UUID defaults and external service generators do
  not become seeded merely by enabling framework test mode. Framework-owned
  sources above are routed explicitly. Audit new component code before claiming
  deterministic coverage for it.

Source searches included `randomUUID`, `SecureRandom`, `ThreadLocalRandom`,
`Math.random`, `new Random`, `nextBytes`, `getRandomString`, `getrandom`, UUID helper
callers, library salt/secret generators, certificate-key generation, framework XML
service scripts and framework browser assets. Test/benchmark generators were
classified separately from runtime sources; comments and `RandomAccess` are not
entropy sources. This is a source audit, not JVM-wide interception of dependencies.
